# Release Note — v0.8.0

**Date:** 2026-07-02
**Branch:** opensearch-mig
**Stack:** Spring Boot 3.4.2 · Java 21 · spring-data-opensearch 1.6.0 · OpenSearch 2.13.0 · PostgreSQL / YugabyteDB

## [0.8.0] — 2026-07-02

### Summary
Completes the OpenSearch integration by upgrading to a Spring Boot 3.4.2-compatible client version, expands the entity hierarchy model to cover the full organisational structure (including geo entities), adds YugabyteDB compatibility, makes the OpenSearch index name configurable, and fixes the test suite broken by the `EntityType` enum-to-class refactor.

---

### Added
- `entity.entityTypeList` property — comma-separated list of valid entity types loaded at startup; drives `EntityType.load()` via `EntityStartupApplicationRunner`. Adding a new entity type now requires only a config change.
- Six new entity types: `ORGANIZATION`, `STATE`, `DISTRICT`, `BLOCK`, `FACILITY`, `POSTING_FACILITY` — enables geo/org hierarchy modelling
- `entity-map.allowed-type-combinations` expanded from 3 to 9 combinations: `ORGANIZATION_POSITION`, `POSITION_ROLE`, `ROLE_ACTIVITY`, `ACTIVITY_COMPETENCY`, `STATE_DISTRICT`, `DISTRICT_BLOCK`, `BLOCK_FACILITY`, `FACILITY_POSTING_FACILITY`, `BLOCK_POSTING_FACILITY`
- `opensearch.index.master-entities` property — makes the OpenSearch index name configurable via env var (`OPENSEARCH_INDEX_MASTER_ENTITIES`); default `master_entities_br`; `MasterEntityDocument` uses SpEL `#{@environment.getProperty(...)}` in `@Document` to read it at runtime

---

### Changed
- `spring-data-opensearch-starter` upgraded `1.5.3 → 1.6.0` — resolves `NoSuchMethodError` (`SearchDocumentResponse` constructor mismatch) caused by Spring Boot 3.4.2 pulling `spring-data-elasticsearch 5.4.x`; `1.6.x` targets Spring Boot 3.4.x and is compatible with OpenSearch server 2.x
- `EntityType` refactored from Java `enum` to `final class` with runtime-loaded type set — removes compile-time enum constants (`POSITION`, `ROLE`, `ACTIVITY`, etc.); only `EntityType.COMPETENCY` remains as a static constant; all other types are validated at runtime via `EntityType.validate(String)`
- `EntitySheetMappingValidator` renamed to `EntityStartupApplicationRunner` — now also handles entity type loading at startup in addition to sheet mapping validation; both responsibilities merged into a single `ApplicationRunner`
- `saveEntityDetailsInES` signature updated — third parameter `userId` (String) added; impl sets `createdBy(userId)` and `createdAt(new Date())` on each OpenSearch document at index time
- `MasterEntityEsServiceImpl` — `findEntitiesBySearchParameter` now calls `EntityType.validate()` on the incoming `entityType` string before building the search query
- `ddl-auto` default changed `update → none` — prevents accidental schema mutation on startup; always set `JPA_DDL_AUTO` explicitly in all environments
- HikariCP connection pool tuned for YugabyteDB stability: `connection-timeout=30s`, `idle-timeout=600s`, `max-lifetime=1800s`, `maximum-pool-size=10`; JDBC URL includes `socketTimeout=60` to prevent hung connections

---

### Fixed
- `NoSuchMethodError: SearchDocumentResponse.<init>` at runtime when calling search endpoints — caused by version mismatch between `spring-data-opensearch 1.5.3` and `spring-data-elasticsearch 5.4.2` (T-004)
- Test compilation failures on Jenkins (`cannot find symbol: method valueOf`, `cannot find symbol: variable POSITION/ROLE`) — caused by `EntityType` enum-to-class refactor not propagated to test classes:
  - `TestDataLoader`: removed `EntityType.valueOf()` calls, changed `competencyLevels()` param from `EntityType` to `String`, fixed `==` to `.equals()` for String comparison
  - `EntityMappingServiceImplTest`: replaced `EntityType.POSITION/ROLE/ACTIVITY` with string literals, removed `.name()` calls on String values, fixed `buildRequest()` parameter type, fixed `any(EntityType.class)` matchers to `anyString()`
  - `MasterEntityServiceImplTest`: replaced `EntityType.ROLE` with `"ROLE"`, fixed `any(EntityType.class)` to `anyString()`
  - `MasterEntityEsServiceImplTest`: replaced `ElasticsearchOperations`/`NativeQuery` mocks with `OpenSearchOperations`/`NativeSearchQuery`; added missing `userId` argument to `saveEntityDetailsInES` call

### Migration Notes

#### Dependency change
`spring-data-opensearch-starter` moved from `1.5.3` to `1.6.0`. No code changes required — the HLRC API surface (`NativeSearchQueryBuilder`, `QueryBuilders`, `OpenSearchOperations`) is unchanged between versions.

#### Environment Variables
| Variable | Change | Action Required |
|---|---|---|
| `OPENSEARCH_URIS` | Existing | Confirm points to OpenSearch 2.x (tested with 2.13.0) |
| `OPENSEARCH_INDEX_MASTER_ENTITIES` | New | Set index name for the environment (default: `master_entities_br`) |
| `JPA_DDL_AUTO` | **Breaking default change** | Must now be set explicitly — default changed from `update` to `none`; use `validate` for production, `update` for local dev only |

#### Config Changes
```properties
# New — entity type registry (add types here to make them valid at runtime)
entity.entityTypeList=COMPETENCY,ROLE,ACTIVITY,POSITION,ORGANIZATION,STATE,DISTRICT,BLOCK,FACILITY,POSTING_FACILITY

# New — configurable OpenSearch index name
opensearch.index.master-entities=${OPENSEARCH_INDEX_MASTER_ENTITIES:master_entities_br}

# Updated — expanded hierarchy combinations
entity-map.allowed-type-combinations=ORGANIZATION_POSITION,POSITION_ROLE,ROLE_ACTIVITY,ACTIVITY_COMPETENCY,STATE_DISTRICT,DISTRICT_BLOCK,BLOCK_FACILITY,FACILITY_POSTING_FACILITY,BLOCK_POSTING_FACILITY

# Changed — ddl-auto default is now none (was update)
spring.jpa.hibernate.ddl-auto=${JPA_DDL_AUTO:none}
```

#### Database
No schema changes in this release. The `additional_properties` column remains (pending T-005).
